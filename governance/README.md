# governance/ —— 约束 AI agent 的纯文件协议

主仓库讲的是「出图流程怎么被判据约束」。这个目录讲同一件事的另一半：**「agent 本身怎么被文件约束」**。

两层的思想是同一个：**把规则写成文件，让机器可执行、让旁观者可审计、让接手者可复核**——判据管图，协议管 agent。

## 三个文件

| 文件 | 管什么 | 一句话 |
|---|---|---|
| [01-answer-first-then-act.md](01-answer-first-then-act.md) | 行为闸门 | 什么动作必须先报清单等批准、执行完怎么交回单对账 |
| [02-decision-ledger.md](02-decision-ledger.md) | 决策留痕 | 每次拍板记一行，只追加不改写，月末对账 |
| [03-mistake-register.md](03-mistake-register.md) | 错题本 | 失败样本入册，每类错挂一道闸门规则，同类错不许犯第二次 |

## 为什么是纯文件，不是框架代码

1. **agent 本来就是文本处理器**。markdown 协议它能直接读、直接执行，不需要额外的运行时。
2. **可 diff、可审计**。规则改动全部走版本控制，谁改的、改了什么，一眼可查。
3. **无依赖**。不绑定任何 agent 框架。换个执行器，协议照搬。
4. **写规则的成本就是维护规则的成本**。没有隐藏在代码里的行为，协议即全部。

## 诚实边界（这套开源不包含什么）

- **真实账本与真实错题本不开**。里面是真实的业务决策与犯错记录，属隐私。开源的只有格式与机制。
- **写者锁的执行代码不含**。协议在 01 里已写清（一个约 50 行的租约式文件锁），任何语言都能照协议自实现。
- **所有示例均为虚构占位**。示例里的条目是为了演示格式编的，不是真实记录。
- **协议不是装上就灵**。这套东西的全部难点在「坚持执行」，不在「写出来」。写出来一天就够，坚持跑几个星期才是门槛。
