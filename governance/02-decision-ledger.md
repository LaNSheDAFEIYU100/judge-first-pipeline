# 02 · 决策留痕账本（decision-ledger 协议）

一句话：**每一次拍板记一行，只追加、不改写；月末用账本对账，用数据回答「这个月的决策靠谱吗」。**

## 解决什么问题

口头拍板的决策会蒸发：一周后没人记得当时为什么选 A，半年后复盘只剩「当初好像是这么定的」。更糟的是 agent（或执行者）会**悄悄改掉台账里对自己不利的历史**。所以账本只有三条硬规则：

1. **追加制**：新决策加在文件末尾，**历史行一个字不许改、不许删**。
2. **无凭证不记**：只记决策与理由，不记凭证、不记敏感内容。账本是决策史，不是资料库。
3. **同一个动作只记一次**：账本条目与流程里的「留痕」条款是同一个动作，拍板终审后顺手追加，不是额外流程。

## 行格式

```
YYYY-MM-DD | 决策：<一句话> | 理由（说不出记「未说明」）| 是否改选 | 验证点：<一句话，可空>
```

字段说明：

| 字段 | 要求 |
|---|---|
| 决策 | 一句话说清改了什么。具体到「哪个文件的哪条规则从 X 改成 Y」，禁「优化了流程」 |
| 理由 | 当事人（用户）的原话或意图。说不出就老实写「未说明」，照常执行不许卡 |
| 是否改选 | 对抗式终审里用户有没有被「最强替代方案」说动。没动写「否」 |
| 验证点 | 这条决策生效后，**预期出现什么；出现什么说明它失效**。写不出验证点的决策等于没立靶子 |

> **验证点是整个账本最值钱的字段。** 它把决策从「拍脑袋留个痕」变成「可事后检验的预言」。月末对账对的就是它。

## 月末复盘（只答三问）

触发：用户问「这个月的决策靠谱吗」。

1. 被采纳的决策里，**验证点兑现了几条**（命中率）。
2. 失效决策有没有**共同模式**（比如：都败在「从单次事故直接跳到硬规则」）。
3. 有没有**该记没记的**（漏记率——翻聊天记录/工单对账）。

复盘产出只回答这三问，不做文摘，不写感想。

## 示例（虚构数据，仅演示格式）

```
2026-11-02 | 决策：示例规则 R-7 的阈值从 0.8 改为 0.7 | 理由：连续两批样张在 0.75 附近误放行 | 否 | 验证点：下两批不应再出现同型误放行；若误拦截率上升超过 5%，说明阈值矫枉过正，回滚
```

## 与其他两份协议的关系

- 上游：**01 号协议**的对抗式终审结束时，触发「留痕一行」→ 就是本账本的一条新行。
- 下游：**03 号协议**（错题本）里的每道闸门规则被修改时，修改决策本身也要进账本。
- 三份文件构成闭环：**闸门管当下，账本管事后，错题本管以后**。
